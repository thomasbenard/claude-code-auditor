## Tools & Releases

**Added**
- `sandbox.allowNestedUserNamespaces`: lets sandboxed Linux commands create user namespaces (Chromium, rootless podman) — the release notes warn this lets them get around the sandbox's file protections.
- `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS`: unattended retry mode notices a usage limit lifted before its reset.
- VS Code: "Running start-up hooks" spinner with screen reader announcement.

**Fixed (selection)**
- Every request failing on Vertex, Bedrock and other providers when the endpoint or a gateway rejects tool search (a 2.1.304 regression); Claude Code now retries without it.
- `/effort` and `/autocompact` not applying when the model name differed from a `modelOverrides` value by case or a `[1m]` tag.
- New worktrees in a bare repository starting from local HEAD instead of the default branch; unchanged subagent worktrees not cleaned up.
- Bash commands on a full disk failing with a raw `ENOSPC`; the error now says the disk is full and nothing ran.
- An MCP server passed by a cloud session or `setMcpServers` being overridden by a same-named server from settings.
- Workflow resume re-running completed `pipeline()` and `parallel()` agents instead of using the run's journal.
- Code Review sometimes skipping the newest commit when several pushes landed during a review.

**Improved**
- `/usage`: each warning is a one-line fix naming its source; `f` applies them (same fixes in VS Code and `/doctor`).
- MCP consent dialogs are less likely to treat an Enter meant for the prompt as Accept.

**Changed (watch out)**
- `allowedMcpServers` no longer filters `managed-mcp.json` stdio servers that use `${VAR}` only in `env` — a server your allowlist excluded now loads on upgrade; use `deniedMcpServers` to keep it off.
- `/artifacts` delete confirmation now uses 1/Enter to keep, 2 to delete, Esc to cancel (`y`/`n` no longer work).
- Code Review re-reviews no longer open with LGTM while earlier blocking findings remain open.
